# 信息架构（Information Architecture）

补充学科框架：信息架构。不处理"好不好看"，处理"信息该不该放在这里、叫什么名字、怎么分组"。

## 核心原则

信息组织方式决定读者能否在 3 秒内判断"这个页面在说什么"、"我需要看哪里"、"与我有关吗"。

## 四步 IA 决策树

### Step 1 — 内容清单（该放什么）

```
需求文档 → 提取所有信息点
  ├─ 主流程信息（读者必须看到才能做决策的）→ 保留，放页面主体
  ├─ 支撑信息（看了更好、不看也不影响判断的）→ 保留，放次级位置或折叠
  └─ 背景/参考信息（没它也能理解结论的）→ 移至 footer/附录/不展示
```

**删除规则：** 任何信息如果读者不读到它就会做出错误决策，放主流程。否则往后放。

### Step 2 — 标签系统（叫什么名字）

```
命名三问：
  □ 读者听到这个名字能猜到内容吗？（不用行业黑话）
  □ 这个名字和页面其他标签是同一种"语言"吗？（动词风格统一、名词风格统一）
  □ 这个名字在读者心智中属于哪个类别？（不跨类）

范例：
  ❌ "TCO 分析" → ✅ "总成本对比：首付 + 3年运维"
  ❌ "技术架构" → ✅ "部署方式：云 vs 本地"
  ❌ "行业洞察" → ✅ "同类学校怎么选的？"
```

### Step 3 — 导航层级（放在哪里）

按输出类型选择：

| 类型 | IA 结构 | 读者心智模型 |
|------|---------|-------------|
| 对比表 | **扁平** — 所有信息在一张表上 | "从上往下扫，比完就有答案" |
| 分析报告 | **层级** — 结论→章节→子章节 | "先知道结论，再选感兴趣的章节深入" |
| 转型指南 | **步骤** — 阶段1→2→3 | "按顺序读，读完就知道怎么做" |

**扁平结构（对比表）规则：**
```
Header（标题/受众定位）
  → 推荐框（结论）
    → 比较表（≤10行，扁平无折叠）
      → 异议框
        → Footer（来源）
```

**层级结构（报告）规则：**
```
Header
  → 核心结论框（3-5条）
    → Chapter 1（核心章节，最长）
      → sub-section（需打断超过500字的连续块）
      → 嵌入表格/卡片支撑论点
    → Chapter 2
    → Chapter 3
    → 附录（非关键数据/详细来源）
      → Footer
```

**步骤结构（指南）规则：**
```
Header
  → 核心结论框
    → Phase 1（当下 = 0-3个月）
      → Phase 2（近期 = 3-6个月）
        → Phase 3（远期 = 6-12个月）
          → 异议框
            → Footer
```

### Step 4 — 扫描路径设计（3 秒测试）

```
读者打开页面 → 3 秒内完成以下扫描：
  1. 标题：这是关于什么的？
  2. 推荐框：什么结论？
  3. 首行内容：这个结论靠得住吗？
```

每个输出在 HTML 写完后，模拟三种角色的扫描路径：

```python
决策者（行长/校领导）：推荐框(0.5s) → 首行对比(1s) → 异议框(1s) → 结论(0.5s)
执行者（技术/财务）：维度索引(1s) → 相关行(2s/行) → 数据来源(1s)
无关角色：标题(1s) → 关掉(2s) → 不需要再读下去
```

如果决策者的扫描路径中没有体验到"逐步确信"的感觉 → 信息顺序或层级有问题。

## 分页/折叠决策规则

什么时候该分章节，什么时候该保持一页？

| 条件 | 决策 | 理由 |
|------|------|------|
| 所有信息能在 1 屏看完 | 不分割 | 用户不需要自己拼图 |
| 信息可分"结论"和"证据"两层 | 一页，证据放后面 | 扫描者只看结论，深读者往下 |
| 信息有 3 个以上互斥的主题 | 分章节 + 锚点导航 | 一个页面的认知负荷太高 |
| 读者来自不同角色，只看不同部分 | 分章节，每章标题指向读者 | 角色各取所需 |

## 空间句法（视觉流动补充）

页面布局不仅是"好看"，它决定了读者眼睛移动的路径：

```
| 空间属性 | 在页面中的对应 | 规则 |
|---------|---------------|------|
| 整合度 | 推荐框位置 | 最高整合度位置放最重要的信息（页面顶部偏左） |
| 可达性 | 信息是否需要滚动才能看到 | 核心结论必须在首屏（无需滚动） |
| 视线深度 | 需要多少次视线跳转才能找到目标 | 目标信息 ≤ 3 次视线跳转 → 超过则加锚点或重构 |
```

**检查：**
```
□ 推荐框在首屏顶部可达位置（无需滚动）？
□ 关键数据维度在页面前 60%（视觉中心区）？
□ 页面上超过 3 种颜色的区域是否 ≤ 3 个（防止视觉碎片化）？
□ 是否有任何信息需要读者"自己拼起来"才知道结论？
```
