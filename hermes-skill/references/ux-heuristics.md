# UX Heuristics（轻量自检层）

生成 HTML 前，用以下 3 条规则快速自检。每条都指向可执行的 CSS/布局检查，不需要视觉反馈。

---

## 1. Fitts's Law — CTA 够大吗？

用户完成一个操作所需时间 = 目标大小和距离的函数。目标越大、越近，点击越快。

**检查：**

```
□ 页面上最重要的操作（"查看方案""立即申请"等）是否有独立的按钮/链接？
  如果只是纯文字链接 → 加按钮样式（padding ≥ 8px 12px）

□ 最小点击区域 ≥ 44px（移动端触控标准，桌面端放宽到 32px）
  检查链接行高、按钮内边距是否达到此标准

□ 主要 CTA 是否在视线路径的终点？
  用户从上到下阅读，CTA 应该在最后一行或者侧边突出的位置
```

---

## 2. Hick's Law — 选项够少吗？

决策时间随选项数量对数增长。选项越多，用户越容易放弃。

**已覆盖：**
- 心理学节 "选择超载" → 控制 ≤10 行
- 信息架构 P0/P1/P2 → 控制信息层次

**补充检查：**

```
□ 页面中同时出现的 CTA/链接 ≤ 5 个（超过则合并或降级为文字链接）
□ 对比表维度 ≤ 10 行（已覆盖）
□ 每章节不超过 5 个子点
```

---

## 3. Jakob's Law — 用户熟悉这个模式吗？

用户大部分时间在使用别的产品，他们期望你的页面和那些产品的模式一致。

**已覆盖：**
- 设计哲学第 6 条 "从已知推未知"
- 快速启动速查表（银行/学校/教育局/科技各有固定模式）

**补充检查：**

```
□ 对比表是否符合"首列维度名，右侧方案列"的行业惯例？
  不创新布局，只在细节上差异化

□ Header 是否符合"标题 + 副标题 + 元信息"的结构？
  不把标题放在右下角或居中以外的位置

□ 核心结论是否在页面顶部？
  用户期望先看到结论，再看到论据
```

---

## 执行方式

这三种检查不需要单独步骤，融合到**自检清单**中：

```
□ CTA 够大吗（Fitts's Law：≥44px，独立按钮）？
□ 选项够少吗（Hick's Law：≤10 维度，≤5 CTA）？
□ 用户熟悉这个模式吗（Jakob's Law：标准布局，不搞创新）？
```
