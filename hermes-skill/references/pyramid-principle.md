# 咨询方法论：金字塔原理（Minto Pyramid Principle）

补充学科框架：咨询方法论。从"三段论"升级为"金字塔结构"——每层结论先行、MECE 分组、SCQA 开场。

## 核心结构

```
结论（总论点）
  ├─ 分组论点 1（MECE 不重叠）
  │   ├─ 证据 1.1（数据/案例）
  │   ├─ 证据 1.2（数据/案例）
  │   └─ 边界条件 1（什么情况下不成立）
  ├─ 分组论点 2（MECE 不重叠）
  │   ├─ 证据 2.1
  │   └─ 证据 2.2
  └─ 分组论点 3（MECE 不重叠）
      └─ ...
```

**规则：** 读者在任何一层读到结论，向下找支持理由，向上找更高层结论。

## SCQA 序言结构

每个输出（对比表/报告/指南）的开头应该用 SCQA 建立共识，而不是直接扔结论。

| 要素 | 含义 | 对比表示例 | 报告示例 |
|------|------|-----------|---------|
| **S**ituation | 背景（读者已知并同意的事实） | "贵行目前在运营两套校园卡系统" | "高校一卡通市场正处于聚合支付转型期" |
| **C**omplication | 冲突（出了什么问题） | "两套系统不互通，学生需要两张卡" | "但各家方案的技术路线差异大，选型困难" |
| **Q**uestion | 核心问题 | "该选哪套系统统一？" | "哪家厂商的方案最适合当前场景？" |
| **A**nswer | 结论（金字塔顶） | "建议采用方案 A，原因如下：" | "经过对比，方案 C 在三个关键维度领先" |

**使用规则：**
- S 必须是读者已经认同的事实——如果读者不同意 S，后续论证无效
- C 必须是 S 的自然结果——"因为 A，所以 B 就出问题了"
- Q 通常不需要写出来（隐含在 C 中）
- A 即是你的核心结论

## MECE 分组（Mutually Exclusive, Collectively Exhaustive）

论证的同层论点必须：**不重叠、不遗漏**。

### 常见 MECE 框架

| 框架 | 适用场景 |
|------|---------|
| 3C（Customer/Competitor/Company） | 行业/竞品分析 |
| 4P（Product/Price/Place/Promotion） | 产品对比 |
| 时间线（短期/中期/长期） | 转型路径/实施建议 |
| 流程（分析/设计/执行/验证） | 方法论对比 |
| 要素拆解（技术/成本/体验/风险） | 方案评估 |

### MECE 检查清单

```
□ 分组 1 和分组 2 是否覆盖了完全不同的维度？
  例如：按"成本"和"体验"分组 → ✅ 互斥
  例如：按"成本"和"预算"分组 → ❌ 重叠

□ 所有分组加起来是否覆盖了所有重要角度？
  例如：技术 + 成本 + 体验 + 风险 → 全面
  例如：只有技术 + 成本 → 遗漏用户体验 → ❌

□ 如果移除一个分组，整体论证是否出现漏洞？
  有漏洞 → ❌ 分组不完整
  没影响 → ❌ 分组不必要，应删除
```

## 纵向逻辑（为什么 → 所以）

金字塔的垂直方向是**问答链**：

```
结论：推荐方案 A
  └─ 为什么？ → 因为成本最低
      └─ 为什么？ → 因为 3 年 TCO 比方案 B 低 30%
          └─ 为什么？ → 因为不需要更换硬件，只需软件升级
              └─ 为什么？ → 因为现有硬件已经是标准架构
```

每向下打开一层，回答上一层隐含的"为什么"。
每向上收束一层，回答本层隐含的"所以呢"。

**检查：** 如果你不能逐层追问"为什么"并得到有意义的答案，金字塔不完整。

## 横向逻辑（归纳 vs 演绎）

同层论点之间的逻辑关系有两种：

### 归纳法（默认推荐）

多个独立证据指向同一结论。适用于对比表。

```
推荐方案 A
  ├─ 理由 1：总成本最低（独立）
  ├─ 理由 2：实施最快（独立）
  └─ 理由 3：本地服务最密（独立）
```

### 演绎法

大前提 → 小前提 → 结论。适用于逻辑推理性强的分析。

```
大前提：实施周期 < 60 天的方案适合暑期施工
小前提：方案 A 实施周期 45 天 < 60 天
结论：方案 A 适合暑期施工
```

**选择：** 归纳法更易读（对比表场景默认用），演绎法更严密（分析报告场景需要时用）。

## 金字塔在三种输出类型中的应用

### 对比表

```
SCQA 开头 → 结论（推荐框，金字塔顶）
  → 维度 1（论点 1）：数据 + 建议
    → 维度 2（论点 2）：数据 + 建议
      → 维度 3（论点 3）：数据 + 建议
        → [不超过 10 个维度，服从 MECE]
          → 异议框（边界条件/例外情况）
```

注意：对比表视觉上是扁平表格，但论证逻辑是金字塔。
"推荐方案哪方面最好？" → 读者只看第一行（锚定）
"推荐方案有哪些不足？" → 读者在中间找到

### 分析报告

```
SCQA 序言 → 核心结论框（3-5 条关键发现）
  → Chapter 1（MECE 分组 1）
    → Sub-section 1.1（证据层）
    → Sub-section 1.2（证据层）
  → Chapter 2（MECE 分组 2）
  → Chapter 3（MECE 分组 3）
    → 异议框
```

每个 Chapter 的第一段是它的"小结论"——读者只读第一章开头就能判断这章是否与自己相关。

### 转型指南

```
SCQA → 核心结论框（转型目标 + 关键阶段）
  → Phase 1：结论先行（"第一阶段要达成什么"）
    → 步骤 1-3（横向归纳）
  → Phase 2：结论先行
    → 步骤 1-3
  → Phase 3：结论先行
    → 异议框（什么情况下这条路不通）
```

## 实操自检

```
□ SCQA 四要素是否完整？S 是读者已知事实？
□ 核心结论在页面顶部，无需滚动？
□ 同层论点是否 MECE（不重叠、不遗漏）？
□ 删除任一层论证，金字塔是否塌了？
□ 每向下展开一层，是否回答了上一层的"为什么"？
□ 横向逻辑是归纳还是演绎？（默认归纳）
□ 边界条件/例外情况是否单独标注？（异议框）
```
