# 语言学：命名与句式规则

## 维度名三层级

| 层级 | 示例 | 理解时间 | 使用位置 |
|------|------|---------|---------|
| 属性（❌） | 支付渠道整合度 | 5s | 不用 |
| 动作（✅） | 能用哪些方式付钱 | 0.5s | th（维度名） |
| 场景（✅✅） | 12点下课3000人同时打饭 | 0.1s | dim-desc（说明） |

## 句式模板

| 类型 | 句式 | 示例 |
|------|------|------|
| 功能 | 能做什么 | 能用哪些方式付钱 |
| 性能 | 做到什么程度 | 对账要多长时间 |
| 安全 | 出了事怎么办 | 监管来查能过吗 |
| 成本 | 要花多少钱 | 从签约到用上要等多久 |
| 服务 | 出问题了找谁 | 系统坏了多久有人到 |

## 标点规则

- 层级分隔用圆点 · （不用顿号、或斜杠/）
- 多项用 <br> 换行（不用顿号）
- 观点句不用感叹号
- 对比双方：描述客观状态，优劣让 badge 说
- 否定标注要说明影响，不写"不支持"三个字结束

## 符号学补充：非语言符号系统

文字不是页面中唯一在传达意义的元素。颜色、位置、间距、形状、留白也在"说话"。

### 颜色符号学

| 颜色 | 在中文企业语境中通常传达 | 检查 |
|------|----------------------|------|
| 蓝色 | 专业/科技/金融/可靠 | 正式场景首选，但全蓝页面会显得"冷" |
| 红色 | 警告/错误/禁止 | 只在负面场景使用，正向不用红 |
| 绿色 | 成功/安全/通过 | 推荐列/正向标注标准色 |
| 橙色 | 注意/警告/中等 | 提醒但不致命 |
| 白色/浅灰 | 专业/简洁/高级 | 大留白="少即是多"，小留白="实用优先" |
| 黑色/深灰 | 正式/权威/高端 | 正文色，深色背景只在特定受众（如科技）使用 |

**自检：** 颜色的符号意义和它的功能意义是否一致？如果红色推荐某方案，用户会困惑（红色在企业语境中=坏）。

### 位置符号学

- **上方 = 重要**（越往上越重要）→ 推荐框在顶部
- **左侧 = 默认/标准**（首列是索引）→ 维度名放左侧
- **右侧 = 可选/高级**→ 选型建议列放右侧
- **中间 = 关注焦点**→ 推荐方案放中间列
- **底部 = 次要/结论**→ footer 和异议框在底部

### 间距符号学

| 间距 | 传达的含义 | 规则 |
|------|----------|------|
| 元素间距 < 8px | "这些是一组的" | 组内元素 |
| 元素间距 16-24px | "这些是不同组的" | 组间距 |
| 元素间距 > 48px | "这里是新章节了" | 章节分隔 |
| 左右大留白 | "这个页面有格调/高端" | 行长 ≤ 75ch |
| 紧凑无留白 | "信息密集/实用" | 执行者场景 |

### 自检

```
□ 颜色的符号意义与功能一致？（红色 = 坏，绿色 = 好，不冲突）
□ 位置符号与常规预期一致？（重要在上面，索引在左侧）
□ 间距在传达正确的分组信号？（同组近，异组远）
□ 如果移除所有文字，光看布局/颜色/位置能判断哪个方案是推荐的吗？
```
